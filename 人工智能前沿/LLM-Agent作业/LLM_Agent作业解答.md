# LLM & Agent 作业解答

## 一、事先思路

本作业不是单纯解释概念，而是要求围绕一个具体场景完成“背景研究-实验设计-系统实现-能力优化-评估测试-报告展示”的闭环。因此我选择“课程学习助教 Agent”作为实验场景：用户可以询问课程知识、让系统拆解学习任务、生成练习题，并要求答案带有知识库依据。

选择该场景的原因是：一方面它和人工智能课程本身贴合，容易展示 LLM 与 Agent 的分工；另一方面它天然需要知识库检索、任务拆解、工具调用、Skill 设计和测试评估，能够覆盖文档中的全部要求。

整体思路如下：

1. 先把系统目标限定为“面向课程资料的学习问答与学习规划”，避免场景过大。
2. 用大语言模型负责自然语言理解和生成，用 Agent 负责意图识别、任务拆解、工具选择和流程控制。
3. 建立课程知识库，通过 RAG 检索课程要求、概念解释和实验说明，减少模型凭空回答。
4. 把常见能力封装成 Skill，例如课程问答、学习计划、练习生成、答案自检。
5. 用测试问题评估意图识别、检索命中、答案正确性、引用一致性和响应时间。

## 二、理论学习和背景研究

大语言模型通常基于 Transformer 架构。Transformer 的核心是自注意力机制，它能够根据上下文动态计算词语之间的相关性，从而处理长文本中的语义关系。大语言模型一般经历三个阶段：预训练、指令微调和对齐优化。预训练阶段通过大规模语料学习语言规律和知识分布；指令微调阶段让模型更好地服从人类任务描述；对齐优化阶段进一步提高回答的安全性、可用性和一致性。

Agent 是一种面向目标的智能体系统。和单次问答式 LLM 不同，Agent 更强调“感知-规划-行动-反馈”的循环。它可以根据用户目标拆解任务，选择合适工具，调用外部知识库或 API，并根据中间结果调整下一步行为。在实际应用中，LLM 通常作为 Agent 的语言理解、推理和生成模块，而 Agent 框架负责流程控制、记忆管理和工具调用。

在教育问答场景中，常见方法包括三类。第一类是直接使用 LLM 进行问答，实现简单但容易产生幻觉。第二类是 RAG，即先从课程资料、教材或作业要求中检索相关片段，再让 LLM 基于检索结果生成答案，能够提高事实一致性。第三类是 LLM + Agent + Tools，把检索、计划、练习生成、自检等功能封装为工具或 Skill，由 Agent 根据用户意图动态调用，适合处理复杂学习任务。

## 三、实验设计

本实验设计一个“课程学习助教 Agent”。系统面向人工智能课程学习者，支持三类核心任务：

1. 课程问答：回答 LLM、Agent、RAG、工具调用等课程相关问题。
2. 学习规划：根据用户目标拆解学习步骤，给出阶段性计划。
3. 练习生成：根据知识点生成自测题，并给出参考答案或评分维度。

系统总体框架包括五层：

1. 用户交互层：接收自然语言问题，输出结构化答案。
2. Agent 控制层：识别意图，拆解任务，决定调用哪些工具。
3. Skill 层：包含课程问答 Skill、学习计划 Skill、练习生成 Skill、答案自检 Skill。
4. 知识与工具层：包含课程资料知识库、RAG 检索器、简单评价工具。
5. LLM 生成层：调用 DeepSeek、Qwen 等大模型 API，或在离线演示时使用 MockLLM 替代。

一次典型流程如下：

用户输入“帮我设计一个 LLM Agent 作业方案”后，Agent 首先识别这是“学习规划/实验设计”意图；然后调用 RAG 从作业要求和课程知识库中检索相关内容；接着将任务拆成背景研究、系统设计、实现、测试和报告五个部分；最后由 LLM 整合为完整回答，并附带引用依据。

## 四、系统实现

原型系统采用 Python 实现，核心文件为 `course_agent_demo.py`。为了保证在无网络和无 API Key 的环境中也能运行，原型使用 MockLLM 模拟大模型生成过程；如果实际接入 DeepSeek 或 Qwen，只需要替换 `MockLLM.generate()` 接口即可。

核心模块如下：

1. `KnowledgeChunk`：表示知识库中的一个文档片段，包含编号、标题和正文。
2. `SimpleRAG`：实现简单关键词检索，根据用户问题和知识片段的词项重合度返回 Top-K 证据。
3. `CourseAgent`：实现意图识别、检索调用、答案生成和调用轨迹记录。
4. `MockLLM`：用于离线演示，模拟 LLM 根据问题、证据和意图生成回答。

Agent 的决策逻辑如下：

1. 如果用户问题包含“计划、步骤、思路、安排”等词，则进入学习规划 Skill。
2. 如果包含“练习、测试题、自测、题目”等词，则进入练习生成 Skill。
3. 其他问题默认进入课程问答 Skill。
4. 每个 Skill 调用 RAG 检索相关知识，再交给语言模型生成最终答案。

可以使用以下命令运行演示：

```bash
python course_agent_demo.py
```

可以使用以下命令运行简单评估：

```bash
python course_agent_demo.py --eval
```

若接入真实大模型 API，可以采用如下替换思路：

```python
class ApiLLM:
    def generate(self, query, evidence, intent):
        prompt = build_prompt(query, evidence, intent)
        return call_deepseek_or_qwen_api(prompt)
```

这样系统结构不变，只替换语言生成模块，Agent、RAG 和 Skill 逻辑仍然可以复用。

## 五、能力构建和优化

本系统设计了四类 Skill：

1. 课程问答 Skill：面向概念解释和课程资料问答，重点保证答案准确、有依据。
2. 学习计划 Skill：面向“如何完成作业、如何复习某知识点”等问题，输出步骤化计划。
3. 练习生成 Skill：根据知识点生成选择题、简答题或设计题。
4. 答案自检 Skill：检查回答是否覆盖问题、是否有引用、是否存在明显矛盾。

RAG 设计方面，可以比较三种方案：

| 方案 | 方法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| LLM-only | 直接让大模型回答 | 实现简单，响应快 | 容易幻觉，难以保证依据 |
| LLM + RAG | 先检索课程资料，再生成答案 | 正确性更高，可追溯 | 依赖知识库质量 |
| LLM + RAG + Agent | Agent 决定调用检索、计划、练习、自检等工具 | 能处理复杂任务，可扩展性强 | 实现复杂度更高 |

优化方向包括：

1. 检索优化：从关键词检索升级为向量检索，例如使用 BGE、text2vec 或其他 embedding 模型。
2. Prompt 优化：要求模型“必须基于检索证据回答，不确定时说明无法判断”。
3. Skill 优化：将问答、计划、练习、自检拆成独立模块，便于复用和调试。
4. 记忆优化：记录用户学习进度和薄弱知识点，用于个性化推荐。
5. 评估优化：建立固定测试集，每次修改系统后都运行同一批测试问题。

## 六、评估和测试

评估指标设计如下：

| 指标 | 含义 | 评价方法 |
| --- | --- | --- |
| 意图识别准确率 | Agent 是否正确识别用户任务类型 | 人工标注测试问题意图，与系统输出比较 |
| 检索命中率 | RAG 是否召回相关知识片段 | 判断返回证据是否包含标准答案所需内容 |
| 答案正确率 | 回答是否符合课程知识和作业要求 | 人工评分或与参考答案比较 |
| 引用一致性 | 回答内容是否能被检索证据支持 | 检查答案与引用片段是否一致 |
| 流畅度 | 表达是否清楚、自然、结构完整 | 人工 1-5 分评分 |
| 响应时间 | 系统从输入到输出的耗时 | 记录平均响应时间 |

测试样例如下：

| 编号 | 用户问题 | 期望能力 | 预期结果 |
| --- | --- | --- | --- |
| T1 | LLM 和 Agent 在课程学习助手中分别负责什么？ | 课程问答 | 能说明 LLM 负责语言理解与生成，Agent 负责拆解、决策和工具调用 |
| T2 | 请给我一个完成 LLM Agent 作业的思路和步骤 | 学习计划 | 能输出背景研究、实验设计、实现、测试、报告的步骤 |
| T3 | 围绕 RAG 和工具调用生成几道自测题目 | 练习生成 | 能生成概念题、设计题和评价题 |
| T4 | RAG 为什么能减少幻觉？ | 课程问答 | 能说明检索证据对生成答案的约束作用 |
| T5 | 如何评价这个系统？ | 评估分析 | 能给出准确率、命中率、满意度等指标 |

离线原型的确定性评估结果可通过 `python course_agent_demo.py --eval` 得到。当前设计中，测试集包含 5 个问题，主要用于验证流程是否跑通、意图是否能正确分类、检索是否能召回相关知识片段。本次运行结果为：`intent_accuracy=1.00`，`retrieval_hit_rate=1.00`，并且回答中包含显式引用编号。真实提交时，如果接入 DeepSeek/Qwen API，建议把测试集扩展到 20-30 个问题，并记录真实的准确率和平均响应时间。

## 七、实验结果与分析

从原型运行结果看，Agent 能够完成基本的意图识别和工具调用。对于“作业思路”类问题，系统会调用学习规划 Skill；对于“测试题”类问题，系统会调用练习生成 Skill；对于一般概念问题，系统会调用课程问答 Skill。每次回答都会返回工具调用轨迹和引用来源，便于分析系统行为。

与直接使用 LLM 回答相比，加入 RAG 后的优势是答案更加贴近课程资料和作业要求；加入 Agent 后的优势是能够处理多步骤任务，例如“先分析要求，再设计系统，再给测试方案”。不足之处是当前原型的检索方式较简单，关键词匹配对同义表达不够敏感；MockLLM 只能用于演示流程，不能代表真实大模型的语言能力。

后续改进可以从三个方面展开：

1. 使用向量数据库和 embedding 模型替换关键词检索，提高语义召回能力。
2. 接入真实大模型 API，提高答案生成质量。
3. 加入多轮记忆，让系统根据用户历史问题调整学习建议。

## 八、结论

本实验围绕“课程学习助教 Agent”构建了一个 LLM + Agent 系统方案。系统将 LLM 用于自然语言理解和答案生成，将 Agent 用于任务拆解、决策和工具调用，并通过 RAG 引入课程知识库以提高答案可靠性。实验设计覆盖了理论研究、系统框架、原型实现、Skill 优化、RAG 对比和测试评估，满足作业文档中对 LLM 与 Agent 综合应用的要求。

最终可以得出结论：LLM 擅长语言理解和生成，但在复杂任务中需要 Agent 提供流程控制和工具调用能力；RAG 能够增强答案依据，减少幻觉；Skill 化设计能够提高系统可维护性和扩展性。因此，LLM + Agent + RAG 是构建课程学习助手、智能客服和知识问答系统的一种有效架构。
