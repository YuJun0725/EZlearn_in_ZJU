# RAG 基线对比说明

## 对比边界

本目录的 RAG 基线只做两件事：

1. 从独立 POI 文档语料中检索 Top-K 候选。
2. 将候选文本交给 LLM 生成 JSON 行程。

它不调用主 Agent 的路线、预算、行程优化和约束校验模块，因此可以作为
“RAG + LLM”基线，与主项目的“结构化知识库 + 工具 + 确定性规划器”进行对比。

## 对比命令

先确认 `.env` 中已经配置 `LLM_API_KEY`、`LLM_BASE_URL` 和 `LLM_MODEL`，再执行：

```powershell
python -m rag_baseline.compare --top-k 8 --output rag_baseline/data/compare_report.json
```

对比脚本使用 `data/comparison_cases.json` 中的 4 个相同需求，记录：

- RAG 生成完成率
- RAG 检索结果数量
- RAG 生成 POI 的知识库 grounding rate
- 必去景点完成率
- 预算合规率
- RAG 生成耗时
- 主 Agent 约束满足率、预算合规率和规划耗时

## 已完成的单案例验证

需求“两个去杭州玩两天，预算1200元，喜欢历史和美术，灵隐寺必去”已成功完成：

- BM25 检索耗时：约 0.64 ms
- Top-K：8
- LLM 生成耗时：约 24.33 秒
- 生成状态：completed
- 生成的 6 个 POI 均来自 Top-K 检索结果

该结果只证明基线链路可运行。

## 4 个案例的实际结果

执行 `python -m rag_baseline.compare --top-k 8 --output rag_baseline/data/compare_report.json` 后：

| 指标 | RAG + LLM | 结构化 Agent |
| --- | ---: | ---: |
| 案例完成率 | 100% | 100% |
| 必去景点完成率 | 100% | 100% |
| 平均知识库 grounding rate | 100% | 不适用 |
| 约束满足率 | 未执行约束校验 | 100% |
| 平均规划耗时 | 26188.25 ms | 1.91 ms |

需要特别说明：RAG 基线虽然在这 4 个案例中生成的 POI 都来自检索结果，但它没有调用预算工具和约束校验器，生成的 `estimated_total_yuan` 多次为 0 或粗略假设值。因此，RAG 的预算合规结果不能与结构化 Agent 的严格预算计算等价，反而体现了当前工具增强方案的价值。
